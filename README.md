# 单词卡 · WordCards

> A local-first terminal flashcard app for managing vocabulary and taking quizzes.

单词卡是一个运行在终端里的本地单词应用。用简单的数字菜单管理生词、进行四选一测验、查看学习统计，所有数据保存在一个可以直接阅读和备份的 JSON 文件里。

无需注册，无需联网，不依赖数据库。克隆下来，`npm install && npm start` 即可使用。

## 功能

- **生词管理**：添加、浏览、删除单词，自动检查重复。
- **随机测验**：每轮随机抽取 5 个单词，四选一作答，答错时显示例句。
- **学习统计**：记录每个单词的答对 / 答错次数，计算正确率，列出最需要复习的单词。
- **本地持久化**：单词和学习记录保存在 `data/words.json`，关闭终端后不会丢失。
- **清空记录**：保留单词，只重置学习进度，重置前需要确认。
- **离线运行**：整个程序只读写本地文件，不需要网络；业务代码仅使用 Node.js 内置模块。
- **终端友好**：支持颜色提示；在不支持颜色的环境里可以用 `NO_COLOR=1` 关闭。

## 环境要求

- Node.js **20** 或更高版本
- npm（随 Node.js 一起安装）

## 安装与启动

下载或克隆本项目，在项目根目录执行：

```bash
npm install
npm start
```

首次启动时，程序会自动创建 `data/words.json`，并写入 10 个示例单词。之后的所有修改都会保存在这个文件里。

目前项目以源码方式分发，还没有发布到 npm，也没有提供全局命令。

## 使用

启动后会出现数字菜单：

```text
  单词卡 · WordCards
  在终端里管理生词，随机抽题测验，数据存在本地。

  ──────────────────────────────────────────────
  10 个单词 · data/words.json
  ──────────────────────────────────────────────
  1  浏览单词        2  添加单词
  3  开始测验        4  删除单词
  5  学习统计        6  清空记录
  0  退出
```

| 菜单 | 说明 |
| --- | --- |
| `1` 浏览单词 | 列出所有单词。未测验的排在最前，其余按正确率从低到高排列，并显示每个词的答题情况。 |
| `2` 添加单词 | 依次输入英文单词、中文意思和例句。单词必填，意思必填，例句可以留空；重复单词（不区分大小写）会被拒绝。 |
| `3` 开始测验 | 从单词本中随机抽 5 个词，每题给出最多 4 个中文选项。答错会显示该词的例句。每轮结束后自动保存战绩。 |
| `4` 删除单词 | 先列出单词，再输入要删除的英文单词；输入 `0` 取消。 |
| `5` 学习统计 | 显示单词总数、测验过的单词数、累计答题数、总正确率，以及最需要复习的 3 个单词。 |
| `6` 清空记录 | 把所有单词的答对 / 答错次数重置为 0，单词本身保留。需要输入 `y` 确认。 |
| `0` 退出 | 结束程序。也可以按 `Ctrl+C`。 |

### 测验示例

```text
  开始测验 · 共 5 题
  根据英文单词，选出正确的中文意思。

  第 1 / 5 题

    serendipity

    1. 有韧性的；能迅速恢复的
    2. 意外发现美好事物的运气
    3. 简洁的；言简意赅的
    4. 漫步；闲逛

  你的答案 > 2
  ✓ 回答正确
```

> 测验至少需要 2 个单词。选项数量取决于单词本里有多少个不同的中文意思；不足 4 个时选项会相应减少。

## 数据

### 保存位置

数据文件是 `data/words.json`，路径相对于**运行命令时的工作目录**。从项目根目录执行 `npm start` 时，文件就在项目的 `data/` 目录下。

程序启动时会把文件读入内存，每次修改后整体写回。建议定期备份：

```bash
cp data/words.json data/words.backup.json
```

### 数据结构

```json
[
  {
    "id": "603fcdf9-be74-4ee3-ba08-1b3d7c85a209",
    "word": "serendipity",
    "meaning": "意外发现美好事物的运气",
    "example": "Finding that little bookshop was pure serendipity.",
    "createdAt": "2026-11-15T00:53:27.306Z",
    "correct": 2,
    "wrong": 1
  }
]
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | 自动生成的 UUID |
| `word` | `string` | 英文单词或短语 |
| `meaning` | `string` | 中文意思 |
| `example` | `string` | 例句，可以为空字符串 |
| `createdAt` | `string` | 创建时间，ISO 8601 格式 |
| `correct` | `number` | 测验答对次数 |
| `wrong` | `number` | 测验答错次数 |

### 重置数据

- **只清空学习进度**：在菜单里选 `6`，单词会保留。
- **恢复成初始状态**：删除 `data/words.json` 后重新启动，会重新生成 10 个示例单词，原有数据不可恢复。

## 开发

### 常用命令

| 命令 | 作用 |
| --- | --- |
| `npm start` | 用 tsx 运行源码 |
| `npm run dev` | watch 模式，修改源码后自动重启 |
| `npm run typecheck` | 只做 TypeScript 类型检查 |
| `npm run build` | 编译到 `dist/` |
| `node dist/index.js` | 运行编译后的版本 |

### 项目结构

```text
src/
  index.ts    菜单循环、用户交互，以及浏览 / 添加 / 删除 / 测验 / 统计 / 重置流程
  store.ts    读写 data/words.json、创建卡片、内置示例单词
  quiz.ts     随机抽题、生成选项、洗牌（纯函数，不做 I/O）
  types.ts    WordCard / NewWord 类型定义
  ui.ts       ANSI 颜色和分隔线
data/
  words.json  运行时生成的数据文件
```

### 设计说明

- 编译后的 `dist/` 不依赖第三方包；源码通过 tsx 直接运行，`typescript`、`tsx`、`@types/node` 只作为开发依赖。
- `quiz.ts` 中的抽题逻辑与界面、文件读写解耦，方便单独测试或替换出题策略。
- 数据量按个人单词本规模设计，启动时整体载入内存；如果单词量非常大，可以改为按需读取或换用数据库。
- 项目目前没有自动化测试套件。欢迎基于 `node:test` 为抽题、排序和数据读写补充测试。

## 常见问题

**Q：第一次启动会覆盖我已有的数据吗？**  
不会。只有 `data/words.json` 不存在时才会写入示例单词。

**Q：可以把数据放到别的位置吗？**  
当前版本固定使用工作目录下的 `data/words.json`。在新目录运行程序时，把旧的 `data/words.json` 复制过去即可。

**Q：怎么换成自己的示例单词？**  
修改 `src/store.ts` 里的 `SEED_WORDS`。它只在数据文件不存在、需要首次生成时生效。

**Q：为什么测验选项少于 4 个？**  
选项来自其他单词的中文意思。如果不同意思的数量不足 3 个，选项就会减少；至少需要 2 个单词才能开始测验。

**Q：终端颜色显示异常怎么办？**  
使用 `NO_COLOR=1 npm start`，或换用支持 ANSI 的终端（如 Windows Terminal、iTerm2、常见的 Linux 终端）。

**Q：可以全局安装成 `word-cards` 命令吗？**  
目前还没有发布 npm 包。可以自行 `npm run build` 后通过 shell alias 指向 `dist/index.js`，或直接使用源码运行。
